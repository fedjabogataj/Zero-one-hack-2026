# Archived experiment results

This directory holds the **persistent record** of each finished training run:
metrics JSON, submission CSVs, model meta, an auto-generated summary, and
optionally the model checkpoint. Anything here is committed to git; the
working directory (`outputs/`) stays gitignored.

> This file is auto-regenerated by `scripts/archive_run.sh` into a
> cross-experiment comparison table once at least one run is archived.
> Until then it just documents the workflow below.

## How to archive a run

After a model finishes training and you've evaluated it (so its outputs land
in `outputs/reports/<tag>/` and `outputs/submissions/<tag>/`):

```bash
# Metrics + submissions only (small, always safe)
./scripts/archive_run.sh outputs/models/transformer_5000.pt

# Same but also copy the ~80 MB checkpoint into results/<tag>/model.pt
./scripts/archive_run.sh outputs/models/transformer_5000.pt --include-model

# Archive everything that has reports under outputs/reports/ in one shot
./scripts/archive_run.sh --all
./scripts/archive_run.sh --all --include-model
```

Then `git add results/ && git commit -m "results: archive <tag>"`. The
script regenerates this top-level README into a cross-experiment table.

## Layout

```
results/
├── README.md                              ← cross-experiment summary (auto-generated)
└── <tag>/                                 ← one per archived run
    ├── README.md                          ← per-run summary with metrics tables
    ├── metrics/
    │   ├── task1.json                     ← next-step
    │   ├── task2.json                     ← sequence completion
    │   └── task3.json                     ← anomaly detection
    ├── submissions/
    │   ├── task{1,2,3}.csv                ← the actual predictions submitted
    │   └── task{1,2,3}.meta.json          ← model info + seed + wandb_run_id
    └── model.pt                           ← only with --include-model (~80 MB)
```

## A note on checkpoint size

Each transformer checkpoint is ~80 MB. Adding a few of them via plain git is
fine. If you commit many, consider [Git LFS](https://git-lfs.com/):

```bash
git lfs install
git lfs track "results/**/*.pt"
git add .gitattributes
git add results/
git commit -m "results: archived experiments via LFS"
```

LFS keeps git operations fast and lets you share large binaries with the
remote without bloating the git history.
